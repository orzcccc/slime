# 预览图生成 UI 预制规则

> 状态：规则已确认  
> 最后更新：2026-11-06  
> 主策划入口：[《史莱姆盲盒》项目策划案](../史莱姆盲盒-项目策划案.md)  
> 关联文档：[最小 UI 框架](UI框架.md)、[桌面岛屿窗口系统](桌面岛屿窗口系统.md)、`.cursor/rules/unity-prefab-authoring.mdc`

## 一、前置条件

开始前逐条检查，任一不满足就停止，并说明缺什么：

- 已读 [最小 UI 框架](UI框架.md)，前提表为：预制设计坐标 `800×800`、实际 Canvas `480×480`、match `0.5`、高保真预览图、部分已有切图。
- 项目已有由 `Assets/Resources/Fonts/KeinannMaruPOP.ttf` 生成的中文 TMP 字体资产。
- 预制直接以文件形式编写和修改，规则见 `.cursor/rules/unity-prefab-authoring.mdc`；禁止生成器脚本。
- 预览图对应 1:1 方形画面，按 800×800 设计坐标拆图；实际窗口统一缩放到 480×480。不是 1:1 时停止，向策划确认画面范围。

## 二、看图分析（先输出，再动手）

分析未写完不摆节点。六项必须全部写出：

1. **适配基线**：方向 = 正方形；设计参考 = `800×800`，实际 Canvas = `480×480`；match = `0.5`；第二种比例 = 不适用（待高 DPI 规则）。
2. **分区表**：每个视觉区域一行。

| 区域 | 类型 | 锚点 | 预览图像素 | 参考分辨率尺寸 |
| --- | --- | --- | --- | --- |
| 例：顶栏 | 顶栏 | `(0,1)`—`(1,1)`，pivot `(0.5,1)` | 高 78 | 高 78 |

   类型只能是：背景、顶栏、底栏、内容区、弹窗、列表、横向条、固定卡片/图标。
3. **重复区域**：哪些是数据驱动列表，条目预制叫什么，预览图上可见几项；哪些是固定个数、直接排进界面。
4. **交互清单**：每个按钮、开关、滑动条、输入框、滚动区域，以及它的热区范围。
5. **文本清单**：每个文本节点的文案、是否单行、字号、对齐方式。读不出的写“待定”。
6. **层级草图**：从根节点到叶子的树，标出哪些是装饰、哪些被脚本访问。

## 三、锚点表

| 节点职责 | anchorMin | anchorMax | pivot | 尺寸写法 |
| --- | --- | --- | --- | --- |
| 铺满父节点的背景、主容器 | `(0,0)` | `(1,1)` | `(0.5,0.5)` | `sizeDelta = (0,0)`，需要留边时用 offset |
| 顶栏 | `(0,1)` | `(1,1)` | `(0.5,1)` | 高度固定，左右拉伸 |
| 底栏 | `(0,0)` | `(1,0)` | `(0.5,0)` | 高度固定，左右拉伸 |
| 顶栏和底栏之间的内容区 | `(0,0)` | `(1,1)` | `(0.5,0.5)` | `offsetMin.y = 底栏高`，`offsetMax.y = -顶栏高` |
| 横向条 | `(0,0.5)` | `(1,0.5)` | `(0.5,0.5)` | 高度固定，宽度拉伸 |
| 弹窗、图标、头像、固定卡片、岛屿主视觉 | `(0.5,0.5)` | `(0.5,0.5)` | `(0.5,0.5)` | `sizeDelta = 设计宽高` |

## 四、生成步骤

每一步都要有输出；失败时停止并报告，不跳步。

| 步骤 | 输入 | 输出 | 失败时 |
| --- | --- | --- | --- |
| 1. 读图 | 预览图 | 第二节六项分析 | 有区域无法归类 → 停止，问策划 |
| 2. 映射节点树 | 分区表 | 节点树，每个节点标注锚点（查第三节） | 某节点在锚点表里找不到对应职责 → 停止 |
| 3. 换算尺寸 | 预览图像素 | 参考分辨率下的宽、高、间距、字号 | 预览图不是 1:1 → 停止 |
| 4. 创建预制 | 节点树、尺寸 | 先做条目预制，再做界面预制 | 引用校验不通过 → 停止并修正 |
| 5. 写入文案 | 文本清单 | 文案写入节点，按测量结果回写文本框尺寸 | 单行文字放不下 → 加大文本框或减小字号，仍不行 → 停止 |
| 6. 检查 | 预制 | `800×800` Game 视图截图，对照第六节失败清单 | 命中任一条 → 回到对应步骤改预制 |

### 第 3 步：换算

- 换算比例 `k = 800 / 预览图宽度像素`。宽、高、间距、字号都乘 `k`，四舍五入到整数。
- 换算结果只用来写尺寸和间距。**禁止**把截图像素坐标直接当作中心锚点下的 `anchoredPosition`。

### 第 4 步：创建预制

- 校正顺序固定：先 Canvas，再父容器锚点，最后子节点尺寸。
- 所有节点 `localScale = (1,1,1)`；禁止用缩放掩盖锚点或尺寸错误。
- 层级尽量浅。根节点下直接放背景、安全区、顶栏、内容区、底栏、弹窗。
- 一个节点同时负责底色和一排子元素时，在同一个物体上挂 Image 和 LayoutGroup。
- 只做纯分组、本身不绘制任何东西的空节点，才只挂 RectTransform。没有独立显隐、适配边界、裁剪或动画的包装层不要建。
- 绘制顺序由兄弟顺序决定：背景在前，文字和按钮在后。
- 有切图时使用切图；随内容拉伸的切图设置 Sprite Border，`Image.type = Sliced`。
- 没有切图时用纯色 Image 并取预览图色值；会随宽度变化的面板、按钮、进度条底图用 `Image.type = Sliced`，节点说明里标“待九宫格”。
- 图标和立绘保持等比：`Image.preserveAspect = true`，不拉伸变形。
- 文本、装饰图片 `raycastTarget = false`；按钮和可点击图片 `raycastTarget = true`。热区等于视觉热区；小图标的热区做在按钮上，不做在图标图片上。
- 只读进度条用 `Slider`：`interactable = false`，删除 Handle，背景和填充都是 Image，靠 `fillRect` 改变填充尺寸。只有扇形、径向填充才用 `Image.Type.Filled`。
- 数据驱动列表只放滚动区域（结构见 [最小 UI 框架](UI框架.md) 第七节），`Content` 保持为空，不把展开后的总高度写死。

### 第 5 步：文案与文本框

- 预览图上能读出的文字直接写进节点，读不出的写“待定”，不留空。预制里的文案只作预览，运行时由集中管理的文案覆盖。
- 预览图上的标题、按钮字、数字为单行：关闭自动换行（`enableWordWrapping = false`），`Overflow = Overflow`，按 `preferredWidth` 回写文本框宽度。
- 说明类文字：写明最大字数和文本框高度，开启自动换行。
- 放不下时加大文本框或减小字号；禁止用省略号截断。

### 第 6 步：检查

- 在 Game 视图 `480×480` 下截图，与按 800×800 缩放的预览图对比位置、尺寸和颜色。
- 第二种比例：不适用（窗口固定）。高 DPI 规则确定后在这里补检查项。
- 进度条分别设为 0%、50%、100%，确认填充没有残影、没有溢出。
- 运行一次 Play Mode，确认 Console 没有缺失引用错误。

## 五、节点命名

节点名用英文驼峰，表达用途，不写当前文案或数值。同一界面内被脚本访问的名字必须唯一。

| 类型 | 后缀 / 名称 | 例子 |
| --- | --- | --- |
| 按钮 | `Button` | `openBoxButton` |
| 文本 | `Text` | `boxCountText` |
| 图片 | `Image` | `slimeImage` |
| 滚动根 | `Scroll` | `inventoryScroll` |
| 条目预制（资源文件） | `Item`，帕斯卡命名 | `InventoryItem.prefab` |
| 遮罩 | `mask` | `mask` |
| 顶栏 | `topBar` | `topBar` |
| 底栏 | `bottomBar` | `bottomBar` |
| 内容区 | `Area` | `contentArea`、`bodyArea` |
| 全屏页 / 弹窗预制根 | `Page` / `Popup` | `MainPage`、`SettingsPopup` |

`ScrollRect` 内部的 `Viewport`、`Content` 保持 Unity 默认名，脚本通过 `ScrollRect` 引用访问。

## 六、失败清单

出现任一条即视为本次生成不合格，必须修改预制，不能通过修改截图来解释：

- [ ] 全屏背景或主内容区使用中心锚点加大尺寸硬铺。
- [ ] 用 `localScale` 适配分辨率或宽高比。
- [ ] 顶栏、底栏离开屏幕边缘，或挡住中间内容。（窗口固定，只在 `800×800` 下检查。）
- [ ] 滚动区域没有 Viewport 裁剪，或 Content 和条目的父节点不一致。
- [ ] 数据驱动列表被复制成多份静态节点。
- [ ] 单行文字换行、溢出或被省略。
- [ ] 图标被非等比拉伸。
- [ ] 装饰图片挡住按钮点击。
- [ ] 存在没有显隐、适配、裁剪或动画职责的空节点。
- [ ] 预览图上能读出的文字在预制里是空的。
- [ ] 预制由生成器脚本创建，或修改后未通过引用校验。

## 七、工具链

执行上述步骤时使用项目内 Skill [preview-to-prefab](../../.agents/skills/preview-to-prefab/SKILL.md) 的脚本：

| 步骤 | 脚本 | 作用 |
| --- | --- | --- |
| 读图 | `slice_preview.py candidates` | 自动识别背景与描边区域，输出带坐标网格的标注图 |
| 切图 | `slice_preview.py run` | 按 JSON 配置并行抠出透明切图，擦除图标/文字并算法补全，输出拼回对比图 |
| 补全 | `ai_fill.py` | 被遮挡区域并行调用 AI 局部重绘，只替换遮罩内像素 |
| 入库 | `install_sprites.py` | 复制到 `Assets/Resources/Sprites/`，生成固定 GUID 的 `.meta` 和参考分辨率坐标 |
| 拼预制 | `prefab_build.py`、`prefab_lib.py` | 按 JSON 节点树创建或就地更新预制，填写引用组件字段 |
| 检查 | `prefab_check.py`、`unity_compile_check.py` | 第 4 步的引用校验；按程序集离线编译 |

这些脚本只直接编辑预制文本，不属于第 4 步禁止的“生成器脚本”（禁止的是在 Unity 中运行时拼装或覆盖 Prefab 的生成器）。
