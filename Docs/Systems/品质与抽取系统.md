# 品质与抽取系统

> 状态：已实现  
> 最后更新：2026-11-06  
> 主策划入口：[《史莱姆盲盒》项目策划案](../史莱姆盲盒-项目策划案.md)  
> 关联代码：`Assets/Scripts/Backend/GameBalanceConfig.cs`、`Assets/Scripts/Backend/Local/LocalGameBackend.cs`、`Assets/Scripts/UI/RarityTextEffect.cs`

## 一、设计目标

- 用十二档品质建立长期收集追求，前期品质易理解，后期品质具备极强的稀缺性和视觉辨识度。
- 随机结果由后端计算，界面只根据后端返回的品质键、名称和颜色展示。开发阶段后端在客户端本地运行，正式版由 PlayFab 云端权威计算，见 [游戏后端与本地存档](游戏后端与本地存档.md)。
- 所有基础概率使用百万分整数权重，避免浮点误差，并保证总和严格为 100%。

## 三、史莱姆配置规则

- 当前每档品质配置一个代表史莱姆，后续可在同一品质下增加多个条目。
- 同品质存在多个条目时，该品质总权重需在条目之间继续细分，不能直接复制整档权重。
- 品质和史莱姆目录配置在 `GameBalanceConfig` 中（正式版迁移到 PlayFab Title Data / Catalog），返回给界面的字段为：
  - `rarity_key`：稳定的程序键。
  - `rarity`：中文展示名。
  - `rarity_color`：基础十六进制颜色。
- 每个史莱姆条目有独立的整数掉落权重；同一品质下所有条目的权重之和必须等于该品质权重，启动时由配置校验检查。

## 四、后端抽取规则

1. 开箱前结算盲盒数量并扣除 1 个盲盒。
2. 取所有掉落权重大于 0 的史莱姆配置，按盲盒品质调整权重。
3. 对总权重使用加密安全整数随机数（拒绝采样，无取模偏差）进行加权抽取。
4. 写入库存、解锁图鉴并重算总 CP，与扣箱一起保存，失败时整体不生效。
5. 返回 `rarity_key`、中文 `rarity` 和 `rarity_color`。

客户端不得根据史莱姆 ID、旧稀有度或颜色反推品质。

## 五、客户端展示规则

- 库存名称与图鉴条目使用后端返回的基础颜色。
- 神器：粉色与白色之间高光闪烁。
- 魔王：暗红文字加黑色描边。
- 战神：暗金文字、橙色描边及高光闪烁。
- 至尊：青蓝至紫色往返渐变。
- 魔神：基于 HSV 色相循环的七彩流光。
- 动态效果只影响视觉，不改变概率、CP 或排序。

## 六、验收标准

- 品质配置必须恰好包含 12 个唯一品质键。
- 所有权重必须为非负整数，总和必须严格等于 `1,000,000`。
- 开箱响应、库存和图鉴必须返回一致的品质键、名称和颜色。
- 顶级品质动态文字效果不得影响普通品质文本，也不得造成持续新增组件或材质实例。
- 自动化测试必须验证品质数量、顺序和权重总和。
