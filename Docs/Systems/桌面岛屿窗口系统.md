## 一、设计目标

《史莱姆盲盒》是一款常驻桌面的陪伴型游戏。游戏不占满屏幕，只有一座漂浮的小岛停在桌面上，玩家照常工作，随时看一眼岛上的史莱姆，或者顺手开个盲盒。

## 二、主界面形态

- 主界面是一片岛屿，培养皿、史莱姆和盲盒产出都在岛上表现。
- 岛屿以外的区域完全透明，玩家能直接看到后面的桌面和其他窗口。
- 背包、盲盒、图鉴等功能页面在岛屿窗口范围内以面板或弹窗展开，不另开新窗口。
- 当前实现：首页以 `Sprites/MainPage/Island/Island.png` 作为主视觉，布局见 [岛屿主界面](岛屿主界面.md)。岛屿贴图开启 Read/Write 以支持按 Alpha 命中。

## 三、窗口规格

| 项目 | 规则 |
| --- | --- |
| 窗口尺寸 | `480×480` 实际尺寸，界面按 800×800 设计坐标等比缩到 0.6；可在设置中按 100/125/150/200% 整体缩放（首次启动按系统 DPI 取最接近的一档），玩家不能拖边框改变大小 |
| 边框 | 无边框，无标题栏和系统按钮 |
| 背景 | 透明，只渲染岛屿和 UI 本身 |
| 显示模式 | 只有桌面窗口一种，不提供全屏或分辨率切换 |
| 任务栏 | 保留任务栏图标；另有系统托盘图标，左键显示/隐藏岛屿，右键菜单（2026-11-08） |
| 置顶 | 默认不置顶，设置或托盘菜单中可开启“始终置顶” |
| 多开 | 只允许运行一个实例 |
| 帧率 | 限制为 30 FPS，失去焦点后继续运行，保证常驻时占用低且能检测鼠标 |

缩放时窗口像素与界面同比例放大，布局比例不变。CanvasScaler 参考分辨率固定为 `800×800`、match `0.5`，实际窗口 `480×480` 时统一缩到 `0.6`；100/125/150/200% 档位对应 480/600/720/960 像素，不改变原有锚点与自适应。规则见 [游戏设置系统](游戏设置系统.md) 第二节。

## 四、拖动与位置

- 玩家按住岛屿、顶栏、底栏、卡片等可见区域可以把整个游戏窗口拖到桌面上任意位置；按钮、下拉框和滚动列表保留自身交互，不触发拖动。
- 拖动结束后保存窗口位置（`PlayerPrefs`：`desktop.window.x`、`desktop.window.y`），退出游戏时也会保存，下次启动时恢复。
- 窗口至少保留 120 像素在所在显示器的工作区内，防止拖出屏幕后找不回来。保存的位置不在任何显示器上时（如拔掉副屏），窗口回到主屏幕工作区中央。首次启动同样居中。
- 支持在多显示器之间拖动。
- 设置中开启“锁定位置”后，按住岛屿不再拖动窗口，控件照常可用。
- “重置窗口位置”把窗口移到主屏幕工作区右下角；缩放后窗口超出屏幕时整体挪回所在显示器工作区内。

## 五、透明区域交互

- 透明区域的鼠标点击穿透到下面的桌面或其他窗口。
- 岛屿图片只在不透明像素上响应点击（贴图开启 Read/Write，Alpha 阈值 0.1）；按钮、卡片等其他可见 UI 按其矩形区域响应。
- 文字和 Alpha 为 0 的布局容器不视为可见区域。
- 仓库、领取/开箱和图鉴弹窗打开时，共用全窗口 `PopupMask`（Alpha 0.35、开启射线检测）；面板空白处及外围都拦截点击，避免穿透桌面导致失焦。点击遮罩不关闭弹窗；关闭后遮罩随弹窗隐藏，恢复主界面的透明区穿透规则。

## 七、技术实现（Windows）

- **启动**：`CoreLoopBootstrap` 在场景加载后挂载 `DesktopWindowController`；场景加载前设置 `480×480` 窗口化、后台运行和 30 FPS。
- **透明**：相机清屏为 `(0,0,0,0)`，关闭 HDR 和后处理以保留帧缓冲 Alpha；窗口样式改为 `WS_POPUP`，并调用 `DwmExtendFrameIntoClientArea`（边距 -1）让 DWM 按逐像素 Alpha 合成。
- **拖动**：鼠标按下时记录光标和窗口位置，按住期间每帧用 `SetWindowPos` 移动窗口，松开后限制在屏幕内并保存。
- **点击穿透**：每帧读取系统光标位置做 UI 射线检测；光标不在可见 UI 上时给窗口加上 `WS_EX_LAYERED | WS_EX_TRANSPARENT`，回到可见 UI 上时移除。
- **拖动判定**：按下时取最上层射线目标（含透明点击区）；它或它的父节点是 Selectable / ScrollRect 时不拖动窗口，因此透明的分段选项、滑条也不会被误当成拖拽区（2026-11-08 调整）。
- **置顶 / 缩放 / 显示隐藏**：`SetWindowPos(HWND_TOPMOST)`；缩放时 `Screen.SetResolution` + `SetWindowPos` 改变窗口尺寸，根 Canvas 有 `CanvasScaler`（按屏幕尺寸缩放）时自动随窗口缩放，否则设置 `scaleFactor`；托盘隐藏岛屿用 `ShowWindow(SW_HIDE)`，游戏继续运行。
- **切档后的样式恢复**：`Screen.SetResolution` 在帧结束后执行，可能把窗口恢复为普通标题栏样式并丢失 DWM 透明状态。缩放请求先跨过当前帧，再重新去掉标题栏/边框、发送 `SWP_FRAMECHANGED` 并延展 DWM 透明区域；通过 `GetClientRect` 检查实际客户区尺寸（允许 1 像素取整误差），连续两帧成功后保存位置和缩放档位。`Screen.width/height` 可能读回延迟或采用不同 DPI 口径，不作为恢复前提或完成判据，避免已成功切到 200% 后误判超时退回 100%。恢复时重设相机透明清屏、置顶和点击穿透；窗口句柄变化时使用新句柄，隐藏状态保留。仅启动定位执行一次，样式恢复允许重复执行。
- **连续切档与失败**：快速切换时取消旧的恢复任务，只完成最后一档，并以第一次切档前的窗口中心为基准；原生恢复最多等待 3 秒，失败时设置页尝试回退到最近已完成的档位（`AppliedScalePercent`）并提示失败，成功后才保存档位。关闭或隐藏设置页不会中止窗口控制器的恢复任务。
- **托盘**：隐藏的工具窗口接收托盘回调，`Shell_NotifyIcon` 登记图标与气泡通知，右键用 `TrackPopupMenuEx` 弹出原生菜单；窗口过程只记录事件，由 `DesktopTrayController.Update` 处理。资源管理器重启（`TaskbarCreated`）后重新登记。
- **Player 设置**：`DesktopWindowPlayerSettings` 在项目加载和每次构建前自动校正，也可通过菜单 `Slime/Desktop/Apply Desktop Window Player Settings` 手动执行。设置内容为默认 `480×480`、窗口化、不可缩放、禁止全屏切换、后台运行、单实例，并关闭 DXGI 翻转模型交换链（开启时透明区域会显示为黑色）。
- **启动**：Player 设置关闭 Unity 启动画面（`SplashScreen.show = false`、不显示 Unity Logo）；无边框、DWM 透明和窗口定位在场景加载前（`BeforeSceneLoad`）执行，不再等到首帧之后，避免启动时先闪出带标题栏的默认窗口。Unity Personal 授权下引擎会强制显示 “Made with Unity” 启动画面，需要 Plus/Pro 授权才能真正去掉。
- 原生窗口能力只在 Windows Player 构建中生效；Unity Editor 中按普通 Game 视图运行，相机背景显示为深灰色便于查看布局。

## 八、验收标准

- 首次启动时窗口为 `480×480`，无边框，位于主屏幕中央，岛屿以外区域能看到桌面。
- 按住岛屿可拖动窗口，松开后位置保持；重启游戏后恢复到上次位置。
- 点击岛屿外的透明区域时，操作落到下面的桌面或窗口；移回岛屿后可以正常点击按钮。
- 窗口不能被拖到完全不可见；显示器配置变化后窗口仍能出现在屏幕内。
- 各功能页面都在 `480×480` 范围内完整显示，没有内容被裁切。
- 无需重启，依次切换 100/125/150/200% 及快速往返切档，窗口最终保持所选大小、无标题栏、岛屿外透明；置顶开/关、透明区点击穿透和窗口中心保持规则均正常。

## 九、缩放修复验证（2026-11-08）

- 编辑器程序集及 Windows 原生分支离线编译通过。
- 临时回归工具直接提取生产方法，模拟 Unity 帧末分辨率生效、尺寸读回延迟、连续切档、句柄重建及系统调用失败；另创建隐藏的真实 Windows 窗口，验证四个尺寸档位的客户区尺寸、无标题栏和 DWM 调用结果，共 73 条检查通过。
- 200% 回退回归：已在旧代码复现“客户区为 960，但 Screen 读回不同尺寸，3 秒后误报失败”。修复后覆盖读回 768/959/960/1200、客户区 1 像素取整，模拟等待 4.5 秒仍保持 200%；窗口丢失、实际客户区尺寸不符及原生调用失败仍走失败处理。
- 上述检查不包含 Unity Player 交换链的实际画面；完整游戏内缩放、透明合成和点击交互仍待 Windows Player 实机确认。
