## 一、页面结构

界面按 800×800 逻辑坐标设计，CanvasScaler 引用分辨率保持 800×800（match 0.5），实际窗口为 480×480，整页等比缩放到 0.6 倍，锚点和自适应布局不变。

| 页面 | 内容与行为 |
| --- | --- |
| M03 领取结果 | 领取后出现，最多 8 个槽位依次翻面；紫、红额外停顿并闪一下；点击任意处跳过；“收下”回主界面，“去开箱”打开本次最高品质盲盒 |
| M04 盲盒仓库 | 红、紫、蓝、绿、白从高到低排列；数量 0 置灰；默认选数量最多的最高品质；一次打开 1 个；概率说明由数值配置实时生成 |
| M05 开箱中 | 抖动、旋转、光束，至少播放 0.8 秒；请求未返回显示“开箱中…”；超过 5 秒显示重试；失败不扣库存 |
| M06/M07 开箱结果 | 品质飘带和立绘；首次获得显示 NEW，重复获得显示“已拥有 ×N”；显示单只 CP 与总 CP 变化；神器及以上增加光晕和火花 |
| T01 图鉴 | 已收集数量、进度条、百分比；全部 / 已收集 / 未收集；4×3 分页；未发现显示灰剪影和 ??? |
| T02 图鉴详情 | 品质、编号、首次获得时间、基础 CP、当前持有、基础概率（白色盲盒口径）与描述；可在背包中查看 |

## 二、后端数据

- 领取响应新增 `claimed_boxes`，顺序与领取前凝聚台一致；客户端只播放这些已确定的品质。
- 开箱响应新增 `is_new`、`quantity`、`base_cp`、`unit_effective_cp`、`total_cp_before`。
- 图鉴条目新增 `number`、`quantity`、`base_probability`、`description`；编号从 1 开始。
- 开箱概率与图鉴基础概率共用 `GameBalanceConfig.SlimeWeightsForBox`，避免公示与结果出现两套算法。
- 图鉴描述来自 `GameBalanceConfig.Slimes`，未来随 PlayFab Catalog 下发。
